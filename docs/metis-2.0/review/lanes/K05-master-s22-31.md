### 2.1 §22 — Required evidence and final handoff (lines 3038–3102)

- **K05-S22-01** (3040–3042) — Completion-state vocabulary is fixed: PLANNED / IMPLEMENTED / VERIFIED / BLOCKED / DEFERRED. VERIFIED requires an identified test/environment/artifact; a manual statement, branch title, mock screenshot, model assessment or planned script is explicitly **not sufficient**. DEFERRED requires the owner's explicit scope decision — a required feature must never be quietly deferred for being difficult. *Priority: MUST (governance invariant, not a feature).*
- **K05-S22-02** (3044) — Each completed milestone's record is a fixed schema: requirement/use-case IDs, changed files, commit/PR, test commands + exits, environment, platform/profile, artifact/trace references, known limitations, rollback. A blocked milestone records the exact missing permission/input/service plus what independent work continues. An unexplained "98% complete" or a bare numeric readiness score is explicitly disallowed as assurance.
- **K05-S22-03** (3046–3048) — Minimum delivery-evidence checklist (verbatim list): repo PRD/ADR update; threat + data-flow matrices; shared capability schemas; reference dispositions; transcript benchmark report; before/after package/runtime metrics; native + React state captures; actual Jev/Laya command demonstrations; portal reconciliation report; install/component security results; native Mac eligibility/signing status; signed Windows artifact provenance; concise user/IT operating guide.
- **K05-S22-04** (3050) — Visual-demonstration requirement: actual command utterance, live caption above the bar, solving orb inside it, real target effect and verification, uncut run, real latency boundaries; audit shows operation route/model/attempt/usage metadata **separately**. Explicit prohibition: "Never stage a successful response over a prerecorded action and label it live."
- **K05-S22-05** (3052) — Additional required-even-if-visual-demo-already-works evidence: Cloudflare route/privacy evidence record + sanitized configuration readback; no-content-sentinel results; device-qualified local-model catalog; Settings lifecycle tests; requested-track speech accounting proof.
- **K05-S22-06** (3054) — Further required evidence: canonical authority/storage matrix; read/write/projection schemas; plaintext-wiki sharing review; actual Dust personal/service connection evidence; conflicting-write/deletion/ACL test results; skill version promotion/revocation demonstration; Settings inventory/task-study results; Teams app registrations/permission matrix; real join/media/status evidence; deployment-specific privacy-owner decision record. Unsupported other-platform routes stay explicitly labeled and disabled (cross-ref COV-38, UC-111).
- **K05-S22-07** (3056) — Installation evidence: a waterfall separating bootstrap bytes / core bytes / optional packs / verification / extraction / sign-in wait / first usable action; remaining-disk and temporary-peak usage recorded. Explicit non-goal-guard: "A smaller bootstrap alone does not satisfy the lightweight requirement" (cross-ref COV-21, SRC-16).
- **K05-S22-08** (3058–3062) — Final Codex report format is an 8-point fixed structure: (1) what actually changed; (2) which required journeys passed on which immutable artifacts; (3) transcript quality by supported slice + remaining limitations; (4) package/memory/latency before/after; (5) actual portal reconciliation + backend states; (6) exact Windows signer/timestamp/hash + release location if published; (7) native Mac implemented/tested vs. signing/PCC/distribution blocked; (8) smallest next steps for remaining blockers. Must finish with a reusable continuation record (branch/SHA, dirty-work ownership, active tasks, decisions, evidence, next commands). Explicit prohibitions: no promising unstarted background work; no claiming installer/portal/provider deployed unless the actual authorized operation succeeded.
- **K05-S22-09** (3064–3102) — The verbatim "paste-in launch instruction" block is the canonical Codex kickoff text; it re-asserts (and must stay in sync with) the 66 stable task IDs, 55 requirement IDs, UC-001–UC-112, and explicitly forbids treating another slice's pass as covering Windows/Laya/core-command evidence ("Never count those still-required integrations as done merely because another slice passes"). §27.2 rule 10 makes this block itself subject to drift-checking (see §2.6).

*Acceptance for this whole subsection, in SAE quality-scenario form:* **Given** a milestone claimed VERIFIED, **when** the Opus planner or a release reviewer inspects its evidence record, **the system responds with** an identified test/environment/artifact reference for every claim, **measured by** absence of any of {manual statement, branch title, screenshot, model self-assessment, planned-but-unexecuted script} as the sole evidence, **under** the full 8-point final-report schema.
