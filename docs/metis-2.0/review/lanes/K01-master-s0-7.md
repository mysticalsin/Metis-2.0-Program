### 2.7 §4 — The command-session contract (lines 305–358)

**4.1 — One audio owner; explicit privacy modes (307–317)**
- **K01-S4-01** (309) — A trusted audio broker owned by the main/native boundary or a qualified native helper — **not** an untrusted renderer self-asserting ownership by tagging PCM "you." Validate IPC sender, lifecycle, session ownership. Document the residual threat model (does not authenticate a human voice or defeat same-user malware).
- **K01-S4-02** (311) — One microphone capture with authorized consumers where OS/architecture permits; meeting transcription and command capture are **logically distinct** — ending one must not silently start/stop the other.
- **K01-S4-03** (313) — Three unambiguous controls: **wake detection enabled**, **command microphone off**, **stop all capture**. Command-off releases its subscription + disables wake/command, but must say so if an enabled meeting is still using the mic. Stop-all stops mic + system-audio + command consumers and revokes pending command authority. **Never label "microphone off" while another Métis feature still captures.**
- **K01-S4-04** (315) — Idle wake detection is opt-in, minimal, on-device, small reviewed detector, bounded volatile buffer. **No** idle/ambient/rolling transcript ever reaches Jev, Laya, analytics, or cloud STT. After a wake boundary, transfer only the authorized command interval; handle the first syllable without uploading the entire pre-wake buffer; the boundary margin policy is tested and documented.
- **K01-S4-05** (317) — Local wake detector is **not** a general local-ASR fallback; the default cloud-only profile stays cloud-only; choosing local speech is an explicit mode/policy transition. Microphone permission needs a real first-use gesture — a UI effect or panel hover may never request it.

**4.2 — Explicit states and transitions (319–334)**
- **K01-S4-06** (321–332) — Ten-state session machine, each with allowed work + visible-result/exit rule: `OFF` (no capture/wake/stream), `ARMED` (local wake only, orb-only per §5.11), `CAPTURING` (bar+caption+glow), `INTERPRETING` (solving orb, cancellable), `AWAITING_APPROVAL` (exact target/consequence, no side effect yet), `EXECUTING` (one committed step, monitored cancellation), `VERIFYING` (no success shown before proof), `COMPLETED` (verified result + permitted receipt metadata), `FAILED/UNKNOWN` (distinguish failed attempt from uncertain side effect), `CANCELLED` (state what already happened; no automatic destructive undo).
- **K01-S4-07** (334) — Use a **monotonic session generation**; late STT/model/helper events from a stopped/replaced owner cannot revive a command, update another session, or commit another side effect. Explicit transitions required for: expiry, sign-out, policy revocation, permission removal, suspend, device replacement.

**4.3 — Fast preparation is not premature action (336–342)**
- **K01-S4-08** (338) — Partial speech may prepare candidates / prefetch non-sensitive app metadata / warm an approved connection, but **must not** execute a side effect on a partial sentence. Test: "open Chrome — actually, don't," "close this tab, not the browser," self-correction, hesitation, negation, delayed final-STT revision. Apply semantic-stability + end-of-command rules scaled to risk.
- **K01-S4-09** (340) — Low-risk already-authorized ops commit only once a complete stable intent+target exist. Text insertion/multi-step binds exact confirmed text/context. **High-impact actions require explicit target-specific UI confirmation** — spoken "yes" alone is insufficient identity/authorization, and **no confidence threshold bypasses this**.
- **K01-S4-10** (342) — Typed commands use the same plan/execution contracts, need a deliberate submit gesture but **no** microphone access. Meeting-transcript lines, web content, subtitles, remote participants, and assistant speech are **never** interpreted as command authority.

**4.4 — Cancellation and graceful close (344–348)**
- **K01-S4-11** (346) — Stop/Escape on the active surface acts locally and promptly **without waiting for Jev or network timeouts**. Configurable global stop chord that does not capture common app shortcuts. A "close app" command resolves the exact process/window and uses graceful close; unsaved-work prompts stay visible and halt the automatic chain; force-quit is a distinct, explicitly-confirmed recovery action, never the default "close."
- **K01-S4-12** (348) — Handle cancellation **at the execution commit point**. Never report "cancelled, nothing happened" after an irreversible step has already committed; reconcile an unknown result before retrying. A new session must not duplicate an old in-flight write merely because the UI reopened.

**4.5 — Exact intent, manual interference, cross-surface stop (350–358)**
- **K01-S4-13** (352) — Treat direct low-risk requests as authorized within the already-authorized local session without repetitive re-approval for a clearly harmless open/focus action; resolve ambiguity before close. Bind camera-activation/capture to the current explicit intent **before** preview can begin, retaining required OS permission/consequence review without re-asking an already-satisfied identical confirmation. This does **not** authorize background capture or photo upload.
- **K01-S4-14** (354) — A second deliberate identical command in a new activation is a **new** operation; repeated callbacks within one activation are deduplicated. Bind pronouns ("there," "that note") to verified outputs of the *preceding step*, not the most convenient foreground object. Pause and re-resolve on focus change/target edit/user taking control — never fight the user for keyboard/mouse.
- **K01-S4-15** (356) — **Local Stop and remote stop are different acknowledgments.** Local Stop immediately revokes the local command generation and stops its permitted capture consumers. "Stop all assistance" also requests shutdown of authorized remote meeting/skill sessions with **per-session acknowledgment**; during a network partition, say remote-stop-unconfirmed — don't claim a bot left because the local animation stopped. Each remote session has a server-enforced revocable lease and a reviewed finite lifetime; test dropped stop messages, broker isolation, lease expiry, reconnect; never resume a stopped occurrence without new authority. The local p95 100ms target (§7) is **not** a guarantee about remote-platform leave latency.
- **K01-S4-16** (358) — On lock/sign-out/user-switch/loss-of-trusted-identity, revoke local privileged authority and suppress confidential previews. Explicit server-side meeting enrollment has separate lifetime/stop rules visible to the user — locking a laptop does not silently terminate or authorize every remote service.
