## 7. Lessons (`lessons/`) — process/regression lessons, several with live engineering value

- **LESSON-001**: keep the visual reference and current scope bound to contract hashes/IDs; never infer scope from a historical screenshot or demo count.
- **LESSON-002**: `display:grid` had overridden `[hidden]`'s native `display:none`, exposing both Stop and Send simultaneously in the lab. **General lesson for any Métis UI code: verify computed visibility, not attribute presence** — a CSS rule can silently defeat `[hidden]`.
- **LESSON-003**: an event handler bound to all `[data-state]` elements instead of `button[data-state]` caused clicks on nested controls to bubble into unintended state resets. **General lesson: scope delegated event handlers to the exact interactive element selector, not a shared data-attribute used by both containers and controls.**
- **LESSON-004**: a preserved (unsent) draft guard made the ARMED orb visually ARMED but silently ignore a new wake — i.e. protecting draft data accidentally broke voice input. **Fix pattern: park the dormant draft separately from wake-acceptance logic; never let data-loss prevention gate a new capture session.**
- **LESSON-009**: (a) a named agent is a versioned definition, never a new privilege or running process; (b) full/partial/visible-only context must never be implied by a screenshot or file title alone; (c) React `onCompositionStart/End`-based property handlers didn't fire reliably in the exercised Chromium path — **use registered event listeners for IME composition, not property assignment**; (d) Read/Teach modes must never produce an actuation proposal — only Draft/Act can; a source change mid-flight must suppress stale completion, not just the later approval step.
- **LESSON-010**: **a later AI-generated proposal (the r9 eight-stage onboarding wizard) must never silently override an explicit earlier owner instruction** (retain existing onboarding) — this is presented as a real mistake that happened during kit iteration and had to be walked back (see also DECISION-RECONCILIATION.md #1 and PRODUCT-STATUS `source_review_note`). Also: matching CLI output or two agreeing JSON reports is not proof of independent review or live software — bind claims to actual commands/outcomes/signed artifacts.
- **LESSON-011** (memory/Hindsight-specific): (1) a memory feature is a deliberate persistent derived-content store — "disabling verbatim source copies does not mean nothing is retained," so **never advertise it as zero-retention**; (2) a provider bank/key/tag is not proof of the user's source access — validate identity/audience/revision/fence before inference, and again before returning content; (3) upstream `is_stale` flags can miss deletions — the app must invalidate contaminated derived results itself via its own tombstones/generations, not trust the upstream flag; (5)/(6) two concrete kit-generation bugs (missing reset binding, task-heading concatenation) were caught only by testing every referenced control **after** HTML assembly, not just testing the source modules in isolation.

These lessons are process guidance for whoever builds Métis 2.0, not bugs in the shipped app — but LESSON-002/003/004 describe exactly the class of bug (visibility/event-scoping/draft-vs-capture race) that would explain UI freezes if the same anti-patterns exist in the real renderer code, which other lanes (L06/L07) should specifically check for.
