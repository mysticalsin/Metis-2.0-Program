## Summary

A blocked main thread cannot report its own stall, and one of the two natural freezes has no stack. A tiny watcher mode in the existing mac-helper samples the main process from outside when the run/alive marker goes stale, so the owner-machine closure gate (M2-0199) has attribution.

## Acceptance

- [ ] mac-helper stall-watch --pid <main> --alive <path> runs as an owned sidecar (in stopAll and the registry), checks the marker's mtime every 5 s, and when it is more than 10 s stale runs /usr/bin/sample <pid> 5 once per stall and at most once per 10 minutes
- [ ] The bundle keeps thread stacks and symbol names only; home-directory paths, user names and file names are redacted, and a test proves no meeting title, transcript text, path or email survives
- [ ] Bundles are kept under userData/diagnostics/stalls/ (at most 10, oldest dropped) and referenced by an app.stall.sampled {bootId, stalledMs} audit event
- [ ] Windows has no sampler: the next boot records prevLastAliveAt and the stall window (residual stated)
- [ ] The watcher's CPU cost is measured in the census; flag off restores the no-sampler behaviour
