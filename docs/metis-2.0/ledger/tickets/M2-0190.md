## Summary

M2-0001's tripwire runs inside vitest, so child processes, swift test, the license-server suite, the scripts/qa harnesses and wrangler (which reads real ~/.wrangler credentials) can go around it, and CI cannot catch it because runners have no OneDrive. Isolate at the OS level too.

## Acceptance

- [ ] swift test (MetisKit and mac-helper), license-server node --test and the scripts/qa harnesses run with HOME, TMPDIR and userData pointed at a per-run sandbox, each with a canary proving no access to ~/Library/CloudStorage
- [ ] Tests that invoke wrangler run with Cloudflare credentials unset, a sandboxed config directory and --local only; a test proves no request leaves localhost
- [ ] docs/metis-2.0/runbooks/test-isolation.md defines the OS sandbox profile for any run on the owner's account: deny read and write on ~/Library/CloudStorage, the Métis userData directory, ~/Library/Keychains and ~/.wrangler; agents never disable the sandbox for test commands (D-28)
- [ ] Order of first runs: CI (macOS and Ubuntu with the honeypot), then the QA account, then the owner's account under the sandbox profile
- [ ] Until D-28 is applied, no agent test command runs on the owner's account at all; CI and the QA account are unaffected

## Verification

- [ ] Sandboxed owner-account dry run: a probe read of ~/Library/CloudStorage is denied
