## Summary

The window.confirm theory is refuted; the leading mechanisms are a main-thread stall from synchronous reads of dataless OneDrive files and a structural no-op reopen in the Hide/Island layout. A JS delay shim cannot pin a libuv thread the way a kernel-blocked hydration does and cannot be loaded into the packaged app if the NODE_OPTIONS fuse is off, so the repro uses OS-level fixtures on the unmodified 1.9.6 artifact, on the QA account with a profile shaped like the owner's. Row numbers refer to the executable repro matrix in docs/metis-2.0/review/prep/FREEZE-HYPOTHESES.md. Part b (M2-0194) reruns the matrix on HEAD with observability. A documented unsuccessful reproduction matrix is a valid outcome.
