## Summary

Without knowing a file is dataless before reading it, 1.9.7 cannot keep History list and search from hydrating cloud-only files. Node's fs.Stats does not expose st_flags and a blocks==0 heuristic misreads APFS-compressed local files, so the existing mac-helper gains a batched stat-flags query. Windows OneDrive placeholders are detected by attribute. The helper binary is rebuilt for 1.9.7 anyway.

## Acceptance

- [ ] mac-helper stat-flags takes a batch of paths and returns st_flags with SF_DATALESS per path via lstat without opening any file; fixtures cover a local file, an APFS-compressed local file and a dataless file
- [ ] Windows: placeholder attributes (FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS, RECALL_ON_OPEN, OFFLINE) are read in one batched query per listing without opening files; the mechanism's cost is measured on the Windows laptop (UNKNOWN until then) and, if it is too slow, placeholders are marked 'unknown' and never read
- [ ] src/main/infra/storage/dataless.ts caches results per (path, mtime, size) and never uses blocks==0
- [ ] Helper missing or failing: classification 'unknown', treated as cloud-only for list and search (never read), audited storage.dataless_probe_failed
- [ ] Lands in the helper order after M2-0027 (M2-0188)
