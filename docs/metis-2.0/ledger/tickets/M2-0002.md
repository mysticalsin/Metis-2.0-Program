## Summary

False closure is the program's biggest risk (ChatGPT audit section 5): persuasive reports and green unit tests are not packaged-product proof. Define one immutable evidence record per level per ticket linking requirement or defect, reproduction, commit, artifact hash, environment, executed test, result, implementer and validator, and a checker that computes closure from those records. It also fixes the dependency rule: artifact dependencies cap closure, decision dependencies do not (work proceeds on the recorded default, labelled ASSUMED).

## Acceptance

- [ ] JSON schema for evidence records: ticket, evidence_level, per-kit_ref status (MET/PARTIAL/BLOCKED/NOT_MET), finding_refs, repro, commit, artifact_sha256 (packaged), environment and host identity, command, exit_code, result, ci_run_id, implementer_session, validator_session, inherited_block; one record file per ticket under docs/metis-2.0/evidence/records/
- [ ] Status vocabulary TODO/IN_PROGRESS/ENGINEERING_COMPLETE/BLOCKED_EXTERNAL/DEFERRED/DONE/CANCELLED documented in docs/metis-2.0/README.md; DEFERRED means shipped flag-off with a recorded owner approval under the degrade order (D-14)
- [ ] Dependency semantics in the README: depends_on lists artifact dependencies; a ticket enters the ready queue when each is ENGINEERING_COMPLETE, DONE, DEFERRED or BLOCKED_EXTERNAL; while an artifact dependency is BLOCKED_EXTERNAL the downstream ticket can close only as ENGINEERING_COMPLETE, its records carry inherited_block, and it becomes DONE when the upstream is DONE and the affected verification is re-run. needs_decision lists D-x decisions: work proceeds on the recorded default labelled ASSUMED, is never capped by the decision, and is re-validated if the recorded answer differs (the check lists those tickets)
- [ ] required_evidence is a set of Stark v9.3.0 levels, which are distinct and unordered (DESIGNED, LOCALLY_TESTED, HOST_CONFIGURED, LIVE_VERIFIED, ACCEPTED, MEASURED); scripts/evidence/check.mjs requires one record per listed level before DONE and rejects any other level value
- [ ] LOCALLY_TESTED needs a CI run ID on the PR head SHA; LIVE_VERIFIED needs harness-produced suite or census output plus the artifact sha256 from the build lane (M2-0187) and the host identity, never prose; MEASURED needs the raw measurement file; ACCEPTED needs the owner's dated statement
- [ ] Fix tickets carry red-before (the new test fails on the parent commit) and green-after runs, both recorded
- [ ] 'Wired for real' is defined and checked: a real client code path with no production stub, a schema-faithful contract fake used only in tests, a one-command live probe script, and BLOCKED with the unblock step visible in the in-app capability matrix; anything less is NOT_MET
- [ ] implementer_session must differ from validator_session (a reviewer never approves its own work); the PR template requires the evidence record path and the reviewing model
- [ ] check.mjs refuses IN_PROGRESS for a ticket over 12 h without slices of at most 10 h
- [ ] scripts/evidence/sample.mjs draws a random 10% of tickets closed since the previous gate for re-execution by a different model; results are recorded as evidence with reexecuted_by
- [ ] Exception by definition of done: the program sign-off (M2-0184) may be DONE with inherited blocks, because the goal defines done as engineering-complete with every external dependency BLOCKED and visible; its record lists each inherited block with its unblock step
