## Summary

Spindumps show the main thread blocked 45 to 85 s inside apfs_materialize_dataless_file_ext. The gateway becomes the only accessor of the meetings root for migrated callers. Admission is one global cap on in-flight meetings-root operations (content plus metadata) of at most the effective libuv pool size minus 2, because stat and readdir on dataless File Provider directories may block too (ASSUMED); a blocked read then can never starve settings writes, audit appends or dns.lookup. Split: the .brain and timer readers are M2-0031 and History list/search is M2-0193.

## Acceptance

- [ ] Gateway is async-only; resolveMeetingsFolder/detectOneDrive move to infra/storage/paths.ts and are injected
- [ ] One global cap on meetings-root in-flight operations (content plus metadata) of at most effective pool size minus 2 (2 at the default of 4); content and metadata are priority lanes under that cap; a permit is held until the OS call settles and a deadline releases only the caller
- [ ] Cap reached returns 'degraded' immediately, never an unbounded queue; in-flight reads are shared per (path, mtime, size); 60 s failure cache; AbortSignal cancels queued work
- [ ] Classification ok|dataless|unavailable|timeout|corrupt|foreign-key|unknown uses the M2-0191 detector before any read; unavailable content is never treated as a deleted meeting
- [ ] ADR-021 records the effective UV_THREADPOOL_SIZE from the packaged diagnostic (M2-0006) and the decision on raising it (Info.plist LSEnvironment on macOS; set before first pool use on Windows), with the measurement that justified it

- [ ] ST-1-W runs on the managed Windows laptop with OneDrive placeholder files and its result is recorded
- [ ] Flag storage.gateway=off restores the previous async paths
