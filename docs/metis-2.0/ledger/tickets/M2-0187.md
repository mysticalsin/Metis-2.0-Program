## Summary

release.yml cannot publish 1.9.7: the macOS job refuses to run without Developer ID and notarization secrets (out of scope and absent), Windows refuses unsigned publication, publication needs both jobs, and the workflow rebuilds from the tag, so 'same sha256 as tested' is impossible. A workflow_dispatch lane builds each candidate once, records provenance, runs the packaged gates on those exact bytes, and lets the owner promote the same bytes to an owner-channel prerelease. It also produces the QA-identity variant, the only form an unreleased build may ever take on the owner's primary account.

## Acceptance

- [ ] workflow_dispatch builds every shipped macOS and Windows target once from a named main commit and writes a provenance JSON (sha256 per asset, commit, workflow run ID, runner image, Electron and Node versions, electron-builder config hash) attached to the run
- [ ] macOS candidates are signed with one stable QA identity (self-signed code-signing certificate or Apple Development, never Developer ID) so TCC grants persist across builds (ASSUMED; verified on the QA account by granting once and confirming the grants survive a second candidate); Windows candidates are unsigned
- [ ] The QA-identity variant (appId com.mantu.asktoto.qa, distinct productName, userData directory and Keychain safeStorage service, legacy llama reaper rule disabled, QA fault hooks compiled in) is built from the same commit in the same run; the shipping-identity candidate runs only on the QA account, the Windows lanes and CI
- [ ] Packaged gates (install/launch smoke, HK, ST-1, RV, EX, census) consume assets by sha256; any rebuild is a new candidate and invalidates earlier results
- [ ] promote-candidate.yml publishes exactly those bytes plus SHA256SUMS as an owner-channel prerelease under D-13 (not Latest, no latest*.yml unless D-13 says otherwise), refuses bytes without a passing evidence record, never rebuilds, and creates the git tag with the workflow token so release.yml is not re-triggered (ASSUMED from GitHub's documented token behaviour; verified in the dry run)
- [ ] Dry run on a no-op commit proves build, hash, download-by-hash and promote-to-draft without publishing
