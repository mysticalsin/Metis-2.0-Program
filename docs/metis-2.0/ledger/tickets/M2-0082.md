## Summary

Verified actions are the core of the HeyClicky upgrade: the registry is filtered by platform and permission before any model call, adapters return typed results and a verifier reads back the postcondition independently. There is never a broad exec tool. REF-01..05 here are the HeyClicky interaction kit's source records.

## Acceptance

- [ ] Registry filtered by platform and permission before any model call; unsupported capabilities (driver replay, universal app support) shown as explicitly unsupported
- [ ] Typed result attempted/verified/failed/cancelled/unsupported/unknown; 'unknown' never displayed as success
- [ ] Verifier reads the postcondition independently; receipts are content-free (audit log plus Operator metadata)
- [ ] Untrusted on-screen instructions refused; arbitrary shell text and security-setting changes refused; graceful close before force
- [ ] The licensed upstream Cua computer-use driver is evaluated against the existing adapters and recorded as adopt, adapt or reject; either way one trusted executor remains and any helper speaks a bounded, versioned protocol with independent outcome verification (HC-04)
