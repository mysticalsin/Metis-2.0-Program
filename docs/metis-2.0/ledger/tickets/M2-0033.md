## Summary

The MAX_INGEST_ATTEMPTS cap does almost nothing: boot resume, the intelligence-index catch-up (force:true), consolidation, dashboard-open requestBackfill and the intelligence pass all reset exhaustion, so after about 8 force-quit relaunches a day the same deterministic failures re-queue and cold-start the local model. One policy function now governs every caller.

## Acceptance

- [ ] Single policy: automatic resume continues genuinely interrupted work; maintenance respects backoff and exhaustion; only an explicit user Retry resets exhaustion
- [ ] unavailable/dataless failures do not consume attempts and wait for an availability change
- [ ] No model-bound maintenance within 120 s of boot, none after an unclean previous shutdown until the first user interaction, at most one at a time, pre-empted by interactive requests
- [ ] The intelligence catch-up no longer runs a force:true backfill on every launch while lastSuccessAt stays 0; prewarm eligibility aligned with ingest routing
- [ ] Dead scheduleConsolidation() removed and the misleading doc comments corrected
- [ ] EX-1..3: seeded ledgers (eligible, backed-off, exhausted, unavailable, completed-unacked) across repeated relaunches: exhausted stays exhausted, completed work is not duplicated, no unauthorized local-model start
- [ ] The scheduler suspends backfill, ingest, consolidation and the intelligence catch-up with deferredReason ledger_unavailable when the ledger is foreign-key, keystore-unavailable, read-only or dataless
- [ ] EX-1..3 also run as real packaged relaunches with seeded ledgers on the QA account, with a census proving no llama-server start in the first 120 s
- [ ] Logic lives in a new module; src/main/index.ts changes are call-site swaps only and land through the merge queue in the declared order (M2-0188)
