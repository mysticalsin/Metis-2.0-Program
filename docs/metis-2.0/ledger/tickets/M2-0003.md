## Summary

quarantineUnusableIndex renames any index.json that fails to decrypt, so a process holding a different key (a test worker, another device on a shared .brain) resets the owner's ledger and forces a full re-ingest, which feeds the heavy-machine loop. Stamp a plaintext index.owner.json with the existing installId on every successful writeIndex, and classify decrypt failures as unparseable, foreign-key or keystore-unavailable. Only an unparseable index owned by this install (or unowned, for backward compatibility) is quarantined; everything else stays byte-identical and opens read-only for the session.
