## 0. How to read this register

Labels: **OBSERVED** = read in this worktree, with the file cited. **DERIVED** = conclusion drawn by M2-0261 from OBSERVED rows. **ASSUMED** = inferred, not proven. **UNKNOWN** = not knowable from here. `LEAD_ACTION:` lines are steps only the lead may do.

Sources: M = `docs/metis-2.0/kit/r11/spec/MASTER.md` (section 24 for R rows, section 19 for the adoption starting decisions); HS = `docs/metis-2.0/kit/v5/baseline/Metis-HeyClicky-Interaction-Upgrade.x/Metis-HeyClicky-Interaction-Upgrade/evidence/sources.json` (retrieved_on 2026-09-25); V6 = `docs/metis-2.0/kit/v6/evidence/SOURCE-REGISTER.json` (checked_on 2026-09-26); INV = `docs/metis-2.0/kit/ID-INVENTORY.json`.

Key column: `kit:id`, the same key the traceability matrix uses. `r11:R25` is R25 of the r11 registry, `hc-kit:REF-01` is REF-01 of the HeyClicky interaction kit (`Metis-HeyClicky-Interaction-Upgrade`) and `v6:REF-01` is REF-01 of the v6 kit. The two REF namespaces overlap on purpose and stay distinct.

Kind column (a reference is never runtime proof):
- **REFERENCE** = a page, README or repository read as a reference. It is not installed behaviour and not runtime proof of anything in Métis, whatever the page says.
- **INPUT** = an owner-supplied file or brief. Its content is a requirement or evidence input, not a verified fact.
- **OWN_SOURCE** = a file of the Métis product repository at the pinned commit. It shows what the source said on that commit, not what any deployment runs.

Decision column: **adopt** = use as the authority or tool named, inside the limits in the security column. **adapt** = take the pattern or idea and implement it independently; no upstream code or bytes are copied. **reject** = do not adopt (as evidence, dependency or product component). MASTER's own labels (ADAPT PATTERN, QUALIFY COMPONENT, ENGINEERING ONLY, DO NOT ADOPT) are kept inside the decision text. QUALIFY COMPONENT is recorded as adapt because no upstream component is accepted before qualification.

Shorthand used in the cells:
- **PIN-DOC** = documentation URL. No version or commit is pinned. Consulted 2026-09-22 (M section 24 intro). Whether the page changed since is UNKNOWN.
- **LIC-DOC** = documentation, not code. Terms of use were not reviewed. UNKNOWN whether any reuse right exists.
- **LIC-UNKNOWN** = licence not audited. M section 19 says to check the actual licence before executing or copying. UNKNOWN.
- **SEC-DOC** = read-only documentation, no code run, and not a certification of Métis.
- **SEC-REPO** = README or source reconnaissance only, not a security audit (M section 19). Hooks, install scripts, network destinations, dependency tree and maintenance were not reviewed. UNKNOWN.

Pin for repository rows is the README blob SHA that M section 24 records, where it records one. A blob SHA fixes the text that was read, not a release. No commit is pinned for any external repository, so every adoption of code needs a fresh pin first (M section 19, last paragraph). That is the rule the clean-room gate of M2-0260 enforces.

HeyClicky rows: the supplied artifact is **HeyClicky 1.0.51 build 61**, DMG sha256 `0c7b2f7b21cc5153e4a3146cdeaff704a67aaf37e08bf06a0117d108edb7b038` (`kit/r11/clicky-study/ARTIFACT.json:4`, `:8-9`). Evidence in this program is STATIC_INSPECTION only; vendor web statements are VENDOR_CLAIM. `tools/trace/check-reference-claims.mjs` fails a row that cites HeyClicky without version, build, sha256 and evidence level, or that cites the changelog without the VENDOR_CLAIM label.
