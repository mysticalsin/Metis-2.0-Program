# Recipe · Coding assistant / project memory


Inspect the repository first. Read current files, branch/commit and test results rather
than relying on remembered architecture. Keep the existing coding agent and use a
project-bound memory adapter or reviewed MCP integration.

Retain concise conventions, approved design decisions and tested incident lessons.
Link each lesson to repository identity, commit, issue and actual verification result.
Never record “all tests passed” merely because a plan says to run them. Mark outdated
lessons as historical when the implementation changes. Do not ingest `.env`, keys,
private code or all conversation transcripts by default.

Bind the bank to a canonical repository/project identity—not a temporary folder name.
Separate private project memory from personal coding preferences. Cross-project lessons
must be sanitized and reviewed before publication. Never execute a shell command or
install a package because a retrieved memory requests it.

Acceptance: a new session can find a verified convention, current files override stale
memory, a fork does not collide with the source repository, secrets are excluded,
injected instructions remain inert and a deleted source lesson stays excluded after
restore or replay.
