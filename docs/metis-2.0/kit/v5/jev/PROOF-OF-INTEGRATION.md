# Minimum proof that JEV is integrated rather than displayed

A mock reply, stored key, imported SDK, provider button or response thrown away with `void result` is not sufficient.

**Required linked trace (metadata only):** actual authenticated tenant/device → effective capability/config revision → qualified model/template/language → approved min-content request and reserved budget → actual provider response/model/usage → validated typed selection → consumption receipt bound to original proposal digest → real host policy/approval → native/API operation → independent result receipt → truthful UI/speech. Include a non-first candidate and arbitrary literal values.

Repeat on a second independent enrolled device using the same server credential revision. Verify no vendor secret in desktop bundles, renderer storage, ordinary response bodies, diagnostic reports or logs. Add before/after key rotation/revocation and failed-replacement evidence.

**Intelligence proof:** authenticated permitted sources → exact source revisions → actual provider batch → inferred relevance/conflict/review label → current-source recheck → grounded display → correction/ACL change/forget with old answer denied. Deterministic facts remain intact and raw content is absent from operations logs. Hindsight writes are a separate approved canonical flow.

**Negative proof:** a deliberate no-op consumer, wrong selected target, model drift, low confidence, changed task authority, missing exact approval, uncertain effect and disabled capability must each fail the relevant acceptance checks. Deterministic commands and Stop remain usable when JEV is disabled or unavailable.

Actual task/voice/control evidence is still NOT_RUN in this kit. The included loopback test connects the real HTTP transport/schema/service/consumer/coordinator to an actual temporary-file write, but its provider result is synthetic and its auth/journal are test fixtures. It proves wiring through the candidate only.
