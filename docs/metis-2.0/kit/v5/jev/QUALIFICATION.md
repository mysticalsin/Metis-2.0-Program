# Real JEV qualification and promotion

## Separate the gates

1. **Code correctness:** deterministic synthetic tests, byte/schema limits, action consumption, current authority, uncertainty, malformed data and negative controls. Passed candidate evidence is in `evidence/FINAL-STATUS.json`.
2. **Account/transport:** authorized synthetic request through the real Operator/vault route to the exact pin. Validate actual response model and schema; record redacted timing/usage, not secrets. NOT_RUN.
3. **Data handling:** actual tenant agreement, retention/region/subprocessor review and route/logging configuration. ZDR availability is not proof it applies. Do not send customer excerpts while unreviewed. NOT_RUN.
4. **Decision quality:** task/template/model/language/cardinality-specific held-out evaluation. Synthetic test distributions are not a calibration dataset. NOT_RUN.
5. **Product integration:** two independently enrolled devices, one central secret, actual decision consumption, live voice/native action/readback/response, source-linked Intelligence and revocation. NOT_RUN.
6. **Operations/release:** distributed budgets, retries, outages, rotation, rollback, artifact signing, native input and actual current repo full CI. NOT_RUN.

## Dataset requirements

Keep reviewed test cases separate from template tuning data. Include English, Québec French, Spanish and Brazilian Portuguese; code switching; accents/Unicode/proper names; negation and self-correction; incomplete references; absent candidates; two identical-looking app titles/accounts; changed focus/source revision; malicious content in labels/excerpts; long irrelevant context; and varied option cardinality. Include arithmetic/date traps, but those expected outputs belong to deterministic code, not a broad JEV truth judgment.

Record expected behavior including **abstention**, permitted clarification and disallowed mutation. Compare deterministic baseline and JEV against exactly the same eligible tasks. A low failure rate measured on only successful responses is invalid: account for timeouts, refusals, malformed replies and overload in the denominator. Report task correctness, dangerous selection rate, literal preservation, confusion matrix, abstention precision/coverage, confidence/probability reliability curves, drift, sample counts and intervals. Thresholds require explicit approval per profile; do not promote the test fixture's `.8` values.

## Measurement

Record monotonic client-local durations for preparation, authorization, reservation, HTTP, validation, consumption, native action, verification and speech playback. Server timestamps alone cannot prove full user latency. The service includes authorization time in its decision deadline; settlement is a separate bounded reconciliation drain. Preserve existing r11 budgets for local Stop, command dispatch and verified warm actions. Stop never waits for JEV; qualification must prove this on an actual device.

Preserve actual per-attempt usage, known zero and unknown/partial states. A timeout may be billable even if the provider does not return counters. Reconcile against actual account metering; do not declare free failed calls. Frozen prices must carry model/date/unit and separate provider versus compute/storage costs. This kit intentionally embeds no vendor tariff as a permanent truth.

## Promotion and rollback

Use `qualification/PROFILE.template.json` as an evidence form, not a runnable policy. Every status begins NOT_RUN and every threshold begins null. A real effective policy is created by the authorized server only after required evidence passes. `configuration.disabled.example.json` is deliberately non-operational.

No generic model-list check is enough: aliases may move and pins may be accepted without appearing in that list. Prove the exact pin with an authorized bounded synthetic request. A successful color-choice probe proves one response and shape, not multilingual action safety, privacy, uptime or full calibration.

Change of pin, template, tokenizer, candidate representation, language, source projection or policy requires requalification proportional to the change. Shadow traffic is disabled unless explicitly approved, scoped, privacy-qualified and budgeted; it cannot execute tasks or share its result with authority. Rollback is a real policy/config version change that invalidates in-flight work.

## Completion rule

Do not close TASK-031 merely because the HTTP adapter works. Require actual applied decisions and two-device credential isolation. Do not close Intelligence work because a Score exists: require source lineage, correction and real canonical authorization. Do not close TASK-032 from a synthetic Laya backend.
