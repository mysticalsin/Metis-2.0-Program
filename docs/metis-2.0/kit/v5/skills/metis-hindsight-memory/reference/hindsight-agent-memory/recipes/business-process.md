# Recipe · Business process learning and reviewed success stories


Store the minimal source-backed context needed to improve a recurring workflow: initial
problem, constraints, decision, intervention, verified outcome and lesson. Keep owners,
source IDs and time bounds clear. Do not let “project completed” in a conversation
replace an approved project record or verified commercial result.

A success-story interview can use recall to avoid repeated questions and identify gaps.
Ask follow-up questions for baseline, intervention, measured result, attribution and
permission to reuse. Mark estimates, self-reported metrics and inferred causality as
such. Do not fabricate ROI or convert a recommendation into an achieved outcome.

Private consultant/user memory stays private. Project data is scoped to authorized
project readers. Publishing an anonymized customer story into a reusable shared bank
requires a separate review: redaction alone may not remove reidentification clues.
The final approved story lives in the canonical content system; Hindsight can index
approved lessons and remember context for later retrieval.

Acceptance: an interviewer remembers consented preferences but cannot reveal another
customer's details; unsupported metrics are flagged; corrections propagate; revoked
publication permission removes access to the story and affected derived summaries.
