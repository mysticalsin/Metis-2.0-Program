# Métis 2.0 — Behavior Upgrade v3 with managed JEV integration

**A full preserved implementation handoff plus executable integration candidates. Not an installed Métis update or release.**

This version makes JEV a real decision consumer in the supplied behavior core: an accepted typed choice selects the original prepared proposal and enters the existing authority/operation/verifier path. It also provides bounded interaction/skill recommendations and source-linked Intelligence annotations, server-only wire/schema logic, managed routing/accounting and central credential lifecycle orchestration.

The full original upgrade is retained. One JEV API key lives in the organizational server vault, not on every employee laptop. JEV augments decisions; it does not replace speech, free-form reasoning, native control, permissions, result verification or canonical memory. A plain deterministic command and local Stop do not become dependent on it.

## Package contents

- `behavior-core/`: the original four modules unchanged, six new TypeScript modules, built JS/declarations and original/new executable tests. No third-party runtime dependencies.
- `behavior/`: previous behavioral requirements and sixty cases preserved, plus JEV requirements and twenty-four JVAC cases. `ALL-ACCEPTANCE.json` contains eighty-four app-level cases, all NOT_RUN.
- `delivery/`: current integration instructions, all 66 root IDs and 20 CXSTEP children preserved, with JEV cross-references.
- `baseline/Metis-Work-Session.zip`: complete earlier r11 implementation handoff, unchanged.
- `baseline/Metis-HeyClicky-Interaction-Upgrade.zip`: original static assessment and interaction integration plan, unchanged.
- `jev/`: specific implementation contract, qualification, non-operational configuration, backlog and new evidence.
- `evidence/`: inherited evidence files unless explicitly rerun/labeled. Prior v2 report, manifest and status are preserved under `jev/evidence/`.

## Verify the candidate locally

From `behavior-core/` with Node installed:

```bash
npm test
npm run test:jev
```

These commands run included compiled code and explicit fixtures, not vendor billing calls or native desktop control. With a compatible TypeScript compiler already installed, `npm run build` rebuilds the ten modules before testing. Rerun inside the actual repository pins and full build graph during integration; historical Métis required Node 22.22.3, whereas these checks ran under Node 22.16.0 and TypeScript 5.8.3.

The optional administrator-only `examples/jev-synthetic-probe.mjs` deliberately refuses without an explicit paid-probe flag and server-provided credential. It is not needed for unit tests and was not executed against JEV here. Prefer the actual authorized Operator admin probe after binding it to the real vault/ledger.

## Not another launcher

This kit does not give this chat remote computer access, start subagents, apply itself to GitHub, install a replacement app or run background work. Integrate through the actual authorized coding checkout, preserving current edits. Never extract baseline archives over the repository, rerun the old fixed-16-file publisher after scope expands, or treat historical snapshots as today's HEAD.

Employees must use Métis itself: click, speak, see real work and hear the verified result. Developer fixtures and prompts are not that final product. Completion requires the actual two-device, native/live decision/action/Intelligence paths, current data-policy qualification, production durability, independent review and original release gates.

No production API keys, private customer data, HeyClicky proprietary code/assets or unapproved external binaries are included.
