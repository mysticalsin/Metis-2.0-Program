# Métis v3 JEV integration: implementation and evidence

**25 September 2026 · full preserved upgrade kit, not an installed app or deployed service**

## What changed

Six original TypeScript modules add a managed JEV integration candidate to the existing four-module behavior core. The action consumer actually uses the chosen original proposal and calls the existing authority/coordinator/verifier; it is not a disconnected HTTP sample or a response discarded with `void result`. Read-only consumers also apply interaction/skill recommendations and source-linked Intelligence labels without giving them execution or canonical-write authority.

The candidate includes:

- Documented System One HTTP/schema handling for Choice, Score and Noul, exact model/answer validation, immutable payloads, byte limits, bounded transport/body/vault waits and redacted errors.
- Managed authenticated-policy ports, separate desktop/Intelligence capabilities, template/language/cardinality qualifications, current-revision rechecks, explicit provider routing and no Laya-only fallback into JEV.
- Mandatory budget/dedupe/circuit/reservation/settlement interfaces with per-attempt usage, current configuration/model identity and cancellation/unknown-accounting behavior. Those interfaces still need real transactional storage.
- Central server-credential administration with synthetic validation before encrypted-vault CAS, exact target/config snapshot, current administrator checks, failed-replacement preservation and truthful ambiguous-commit reconciliation. No secret is returned; successful storage remains Checking.
- Literal/candidate binding, confidence/abstention handling, durable consumption callback, existing exact approval/native target checks, real effect verification and truthful outcomes.
- Independence of deterministic simple commands, local Stop/status/speech-only controls and source-backed canonical facts. JEV is not a speech model, a grant issuer, a native driver or a result verifier.

Built JavaScript and declaration files are included. The new code has no third-party runtime dependency. The original authority/coordinator/native-lease/voice source files remain byte-identical to v2. No application source import, existing GitHub checkout, installed Mac profile, tenant account or cloud configuration was changed.

## Observable negative checks

The new tests detect consuming the first instead of the returned proposal, ignoring uncertainty, model drift, missing post-response/final freshness checks, converting unknown usage to zero, ignoring selection settlement and forcing JEV under Laya-only policy. They also exercise stale Stop/correction/signout, incomplete identity, exact approval, independent literal matching, revoked canonical sources, admin rotation conflicts, probe failure and postcommit uncertainty.

The loopback provider does not call TypeSafe. It uses a deliberate local response wrapper so the production fixed-origin check remains intact while exercising a local HTTP server. No production option accepts a custom vendor URL. Synthetic multilingual text proves preservation and schema handling, not JEV language quality or STT accuracy.

## Current API research

Primary TypeSafe documentation and OpenAPI were checked on 25 September 2026. They identify the typed System One interface, `jev-1.13.0` as a documented candidate pin, independent questions, Choice/Score confidence and Noul yes-probability, and language/model-change caveats. References and scope are in `jev/evidence/PRIMARY-SOURCES.json`.

Data-retention review remains mandatory. Enterprise ZDR availability, a synthetic health response, no-training language or an HTTP no-store flag does not establish the actual organization's data-processing terms or provider retention. No customer context was sent to JEV here.

The candidate intentionally supports a stricter safe subset: text-only Score labels for exact legend matching, bounded candidates/questions/bytes, fixed origins, explicit fallback and no production-default confidence thresholds. It must be qualified against the actual account/transport. The illustrative disabled config and null qualification form cannot enable the service.
